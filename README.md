# ather-content

محتوى تطبيق **أثر** الذي يُحدَّث من هنا، لا من إصدار جديد للتطبيق.

التطبيق يقرأ هذه الملفات عبر روابط GitHub Raw عند فتح الشاشة، ويحتفظ بآخر
نسخة ناجحة على الجهاز. فأي تعديل تدفعه إلى الفرع `main` يصل المستخدمين عند
التحديث التالي للشاشة — بدون بناء ولا رفع على المتاجر.

| الملف | الشاشة | الرابط المباشر |
|---|---|---|
| `reels.json` | الريلز | `https://raw.githubusercontent.com/m7hamed-dev/ather-content/main/reels.json` |
| `community.json` | المجتمع | `https://raw.githubusercontent.com/m7hamed-dev/ather-content/main/community.json` |

> روابط Raw تمرّ عبر ذاكرة CDN مؤقتة، فقد يتأخر ظهور التعديل بضع دقائق.

**لتحرير المحتوى بلا Git:** <https://m7hamed-dev.github.io/ather-content/admin.html>
— صفحة واحدة تقرأ الملفين وتكتبهما عبر GitHub API بتوكنك، وترفع الصور إلى
`images/` نيابةً عنك.

## reels.json

```jsonc
{
  "version": 1,              // رقم صيغة الملف — ارفعه فقط إن تغيّر الشكل
  "updatedAt": "2026-11-03", // للتوثيق لا غير
  "items": [
    {
      "id": "reel-001",                   // مطلوب، فريد، وثابت لا يتغيّر
      "title": "عنوان المقطع",             // مطلوب
      "description": "سطر تحت العنوان",    // اختياري
      "videoUrl": "https://.../clip.mp4",  // رابط مباشر لملف فيديو
      "imageUrl": "https://.../card.jpg",  // صورة تُعرض بملء الشاشة
      "linkUrl": "https://...",            // صفحة تُفتح خارج التطبيق
      "thumbnailUrl": null                 // صورة معاينة الفيديو
    }
  ]
}
```

**العنصر يحتاج `id` و`title`، ثم واحدًا على الأقل من الثلاثة:**

| الحقل | ما يفعله في التطبيق |
|---|---|
| `videoUrl` | يُشغَّل داخل الشاشة. **رابط مباشر لملف** (‎`.mp4`‎ غالبًا)، لا صفحة مشاهدة. |
| `imageUrl` | تُعرض الصورة بملء الصفحة بلا مشغّل. الأنسب عمودية 9:16. |
| `linkUrl` | يظهر زرّ «فتح على …» يفتح الصفحة خارج التطبيق. |

يمكن الجمع بينها: صورة + رابط تعطي صفحة لها خلفية وزرّ. والعنصر الذي ينقصه
الثلاثة جميعًا يتخطّاه التطبيق.

> **رابط صفحة في `videoUrl`؟** إن كان المضيف إنستغرام أو يوتيوب أو تيك توك
> أو ما شابه، يعرفه التطبيق ويعامله معاملة `linkUrl` تلقائيًا: لا محاولة
> تشغيل فاشلة، بل زرّ «فتح على …».

### ⚠️ المقاطع الحالية مؤقتة

الثلاثة الموجودة الآن هي مقاطع اختبار عامة، وُضعت ليثبت أن السلسلة تعمل من
طرفها إلى طرفها. **استبدلها بمقاطعك**؛ لا حاجة لأي تغيير في التطبيق.

## community.json

```jsonc
{
  "version": 1,
  "updatedAt": "2026-11-03",
  "items": [
    {
      "id": "c-001",                      // مطلوب، فريد، وثابت
      "title": "عنوان النصيحة",            // مطلوب
      "content": "نصّ النصيحة",            // مطلوب
      "imageUrl": "https://.../card.jpg", // اختياري — صورة تتصدّر البطاقة
      "date": "2026-11-03",               // اختياري
      "category": "تذكير"                  // اختياري — يظهر كوسم على البطاقة
    }
  ]
}
```

`imageUrl` اختياري تمامًا: الرسالة بلا صورة تظهر كما كانت، والرسالة بصورة
تتصدّرها الصورة مقصوصةً بنسبة **16:9**. النص الطويل يُقصّ في القائمة ويُقرأ
كاملًا عند الضغط على البطاقة.

## الصور

الصور تعيش في مجلد `images/` داخل هذا المستودع، ويشير إليها الحقل برابط Raw:

```
https://raw.githubusercontent.com/m7hamed-dev/ather-content/main/images/اسم-الملف.jpg
```

أسهل طريق: زرّ **«رفع صورة…»** في صفحة الإدارة. يصغّر الصورة إلى 1600 بكسل
على أطول ضلع ويحوّلها JPEG قبل الرفع، ثم يملأ الحقل برابطها. ويمكن بالطبع
رفعها يدويًا من واجهة GitHub ونسخ رابط Raw.

| أين | النسبة المقترحة | ملاحظة |
|---|---|---|
| بطاقة المجتمع | 16:9 (مثلًا 1200×675) | تُقصّ لتملأ العرض |
| ريل مصوَّر | 9:16 (مثلًا 1080×1920) | تُعرض كاملة بلا قصّ |
| معاينة فيديو | نسبة الفيديو نفسه | تظهر ريثما يفتح المقطع |

ابقَ تحت ~300 ك.ب للصورة الواحدة: التطبيق يحمّلها على شبكة الهاتف ويخزّنها
مؤقتًا. والصورة التي يفشل تحميلها لا تكسر البطاقة — يظهر مكانها رمز صامت.

## قواعد التحرير

- **`id` ثابت لا يُعاد استخدامه.** التطبيق يميّز العناصر به.
- الحقول غير المعروفة تُتجاهل، فإضافة حقل جديد لا تكسر النسخ القديمة.
- العنصر الذي ينقصه حقل مطلوب يُتخطّى وحده، ولا يُسقط بقية الملف.
- تحقّق أن الملف JSON صالح قبل الدفع:
  ```bash
  python3 -m json.tool reels.json > /dev/null && echo ok
  ```

## ماذا يحدث عند انقطاع الاتصال

جلب شيئًا من قبل، يعرض رسالة وزرّ إعادة محاولة.
